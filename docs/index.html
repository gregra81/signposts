signposts

Your corrections shouldn't die with the session.

"Staging is read-only." "That file is generated, don't edit it." "We don't use that pattern here." signposts turns what you tell Claude Code into markdown in your own repo, opened as a pull request, so the next person's Claude already knows. 

curl -fsSL https://gregra81.github.io/signposts/install.sh | bash

Needs Node 24+. No account, no API key, no server — the source is on GitHub.

The knowledge is already being produced. Nothing catches it.

Every working session with an agent contains corrections that are not in the code and not in any doc:

  • "Don't run migrations against staging, the ETL job owns writes there."
  • "That permissions error is a read-only replica, not a network problem."
  • "The platform team owns that module. We don't fork it."

Then the session ends and it is gone. The next developer hits the same wall, and so does the next agent, because none of it was ever written down anywhere a person or a model would look.

How it works

  1. It reads the transcripts you already have. The sessions Claude Code wrote to your disk, once they have been idle a day, stripped down to the human turns.
  2. Your own Claude session does the thinking. signposts pauses and asks it to extract, criticise and classify — on the plan and quota you already pay for.
  3. A pull request appears. You review it like any other. Anything that edits, deletes or contradicts existing knowledge waits for you first.

Why it is safe to leave running

Nothing leaves the machine

Transcripts are read locally and the search index is local. There is no server and no account.

No new API key

The reasoning is answered by the Claude Code session you are already in.

Your working tree is untouched

Proposals are committed through a separate worktree onto their own branch, mid-task or not.

Nothing merges itself

Every signpost arrives as a pull request a person approves, and contradictions always stop.

Get started

curl -fsSL https://gregra81.github.io/signposts/install.sh | bash
cd your-repo
signpost init

Then add the plugin, which carries the hook, the commands and the search server:

/plugin marketplace add gregra81/signposts
/plugin install signposts@signposts

After that you ask Claude to run signposts and read the pull request when it arrives. The README covers the commands you can still type by hand.
