Why not agent memory?

Claude Code's auto memory already notes your corrections, but its docs call it "machine-local", and nobody reviews it. Memory plugins work the same way: per developer, stored outside the repo. Keep them for your personal preferences. signposts is for what the whole team needs to know.

How it works

Everything runs on your laptop. The only LLM is the Claude Code session you already have open.

  1. Reads finished sessions

    The transcripts Claude Code already keeps, with secrets redacted locally.

  2. Keeps what code can't tell you

    Your session drafts claims, and a critic rejects anything the code, config or docs already say.

  3. Checks what's recorded

    A duplicate merges into the existing signpost. A contradiction is flagged.

  4. Opens a pull request

    Committed from a separate worktree, so your checkout is never touched.

Questions

Does it check that a signpost is true?

No. It checks that a claim is new and not hedged. The pull request is where someone who knows says "that changed in April".

What does it cost?

Tokens from your Claude Code plan. In our 33-session eval set the median was about 10k tokens per session, and the real figure is a little higher.

What leaves my machine?

Redacted excerpts go to Claude through your own session. The branch goes to your GitHub origin. There is no signposts server.

What do I need?

Node 24+, git, and a repo with a GitHub origin. It captures from Claude Code only, but the output is plain markdown any agent can read.
